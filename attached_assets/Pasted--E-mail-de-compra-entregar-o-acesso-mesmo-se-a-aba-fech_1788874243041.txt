# E-mail de compra — entregar o acesso mesmo se a aba fechar

Contexto: hoje, quando alguém paga o Pix, o acesso só chega se a aba do checkout
continuar aberta (a tela consulta o servidor a cada 4s e redireciona). Se o
celular matar a aba, se a pessoa fechar, ou se passar dos 15 minutos, ela paga e
fica sem nada — porque **nenhum e-mail é enviado na compra**. Isso já aconteceu
com uma compradora real.

Faça **apenas** as três partes abaixo. Não refatore nada, não mexa em layout de
outras telas, não altere o fluxo de login existente.

---

## PARTE 2 — `artifacts/api-server/src/routes/connection.ts`

Existem duas funções já prontas: `grantSessionAccess()` e `notifyGrantedAccess()`
(essa última já dispara a notificação push para o dono). Vamos pendurar o e-mail
no mesmo lugar.

**2.1** — Em `grantSessionAccess`, o `.returning({...})` hoje devolve só
`buyerName`, `packageName` e `accessGranted`. Adicione dois campos:

```ts
    .returning({
      id: sessionsTable.id,
      buyerName: sessionsTable.buyerName,
      buyerEmail: sessionsTable.buyerEmail,
      packageName: sessionsTable.packageName,
      accessGranted: sessionsTable.accessGranted,
    });
```

**2.2** — Em `notifyGrantedAccess`, depois do bloco do push que já existe,
adicione o envio do e-mail:

```ts
  if (session.buyerEmail) {
    const baseUrl = process.env.PUBLIC_BASE_URL || "https://www.perguntasdeconexao.com.br";
    const payload = buildPurchaseAccessEmail({
      buyerName: session.buyerName,
      accessUrl: `${baseUrl}/acesso/${encodeURIComponent(session.id)}`,
      loginUrl: `${baseUrl}/login`,
    });
    void sendEmailViaBrevo({
      to: session.buyerEmail,
      toName: session.buyerName,
      subject: payload.subject,
      htmlContent: payload.htmlContent,
      textContent: payload.textContent,
    })
      .then((result) => {
        if (!result.ok) {
          req.log.error({ error: result.error }, "Purchase access email failed");
        }
      })
      .catch((error) =>
        req.log.error({ err: error }, "Purchase access email threw"),
      );
  }
```

Adicione o import no topo do arquivo:
```ts
import { buildPurchaseAccessEmail, sendEmailViaBrevo } from "../lib/brevo";
```

**Importante — não precisa de trava contra e-mail duplicado:** `grantSessionAccess`
só devolve uma linha quando o acesso saiu de `false` para `true`. Se o webhook
chegar duas vezes, a segunda não devolve nada e o e-mail não é enviado de novo.

## PARTE 3 — `artifacts/perguntas-de-conexao/src/App.tsx`

Não existe rota de acesso direto hoje. Crie uma, bem simples, ao lado das outras
(perto de `<Route path="/onboarding" ...>`):

```tsx
<Route path="/acesso/:sessionId" component={AccessLinkRoute} />
```

E o componente (pode ficar logo acima do `Router`):

```tsx
function AccessLinkRoute({ params }: { params: { sessionId: string } }) {
  useEffect(() => {
    if (!params.sessionId) return;
    safeSetItem("conexao-session", params.sessionId);
    safeSetItem("conexao-role", "owner");
    window.location.href = "/onboarding";
  }, [params.sessionId]);
  return null;
}
```

Ele só guarda a sessão no navegador (exatamente o que o checkout já faz quando o
pagamento confirma) e manda para `/onboarding`. A verificação de acesso de
verdade continua acontecendo no `/app`, como já acontece hoje — esta rota não
concede nada por conta própria.

## Depois de aplicar

1. `pnpm run build` tem que passar.
2. Confirme que a variável `PUBLIC_BASE_URL` existe no ambiente (se não existir,
   o fallback do domínio já está no código).
3. Teste: faça uma compra de teste com Pix e um e-mail seu. Assim que o pagamento
   confirmar, o e-mail tem que chegar. Clique em "Abrir meu baralho" **numa aba
   anônima** — tem que abrir o onboarding com o acesso liberado.
4. Deploy.
