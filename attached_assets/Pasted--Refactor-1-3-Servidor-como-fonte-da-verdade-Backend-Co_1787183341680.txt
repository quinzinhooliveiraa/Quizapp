# Refactor 1/3 — Servidor como fonte da verdade (Backend)

**Contexto:** hoje o estado de identidade e onboarding vive no `localStorage` do navegador, causando bugs quando alguém troca de papel (dono ↔ convidado) ou muda de aparelho. Solução: servidor guarda onboarding-complete no banco, endpoints já retornam isso, e temos rotas pra marcar como completo.

**IMPORTANTE: aplicar direto nos arquivos. Não é pra salvar como asset.**

## 3. Novas rotas pra marcar onboarding como completo

Adicionar em `artifacts/api-server/src/routes/connection.ts` (junto das outras rotas de session/invite):

```ts
// Dono marca onboarding como completo
router.post("/access/sessions/:sessionId/complete-onboarding", async (req, res): Promise<void> => {
  const sessionId = req.params.sessionId;
  if (!sessionId) { res.status(400).json({ error: "Sessão inválida" }); return; }
  const [updated] = await db.update(sessionsTable)
    .set({ onboardingComplete: true })
    .where(eq(sessionsTable.id, sessionId))
    .returning({ id: sessionsTable.id });
  if (!updated) { res.status(404).json({ error: "Sessão não encontrada" }); return; }
  res.json({ ok: true });
});

// Convidado marca onboarding como completo
router.post("/access/invites/:token/complete-onboarding", async (req, res): Promise<void> => {
  const token = req.params.token;
  if (!token) { res.status(400).json({ error: "Token inválido" }); return; }
  const [updated] = await db.update(invitesTable)
    .set({ onboardingComplete: true })
    .where(eq(invitesTable.token, token))
    .returning({ token: invitesTable.token });
  if (!updated) { res.status(404).json({ error: "Convite não encontrado" }); return; }
  res.json({ ok: true });
});
```
