# Refactor 2/3 — Servidor como fonte da verdade (Frontend)

**Contexto:** backend agora tem `onboardingComplete` no banco (dono e convidado), e endpoints retornam esse campo. Este prompt faz o frontend **ignorar** o `localStorage 'conexao-onboarding-complete'` pra decidir se onboarding tá completo — passa a ler direto do servidor. E quando o onboarding termina, chama endpoint pra salvar no servidor.

**IMPORTANTE: aplicar direto nos arquivos. Não é pra salvar como asset.**

## Verificação
1. **Como admin**, login → cai em /onboarding (porque servidor diz onboardingComplete=false pra tua session).
2. **Passa todo o onboarding** → no fim, cai em /app. Servidor recebeu POST /complete-onboarding.
3. **Fecha o navegador, abre de novo em janela anônima**, faz login → cai DIRETO no /app (porque servidor lembra que já fez).
4. **Cria convite, aceita no mesmo navegador (admin logado)** → agora vai passar pelo onboarding do convidado inteiro (porque servidor diz que aquele invite ainda não completou), incluindo step de email. No fim, cai no /app como convidado.

Se tudo passar, o problema de "localStorage sujo" está estruturalmente resolvido. Depois vem o **Prompt 3/3 (cleanup)** que remove os últimos vestígios do `localStorage 'conexao-onboarding-complete'` e outros checks legado.
